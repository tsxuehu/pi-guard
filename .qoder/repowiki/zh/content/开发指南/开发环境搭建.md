## 简介
本文档提供 pi-guard 开发环境的完整搭建步骤，从零开始，一步步完成所有组件的安装、配置与验证。Pi-Guard 是一个基于树莓派的智能监控系统，包含 C++ 代理程序、Node.js 服务器、React 前端和 SRS 流媒体服务四个主要组件。

## 系统要求
| 项目 | 要求 |
|------|------|
| 操作系统 | Ubuntu 22.04+ / Raspberry Pi OS (Debian-based) |
| 架构 | x86_64 或 ARM (树莓派) |
| CMake | ≥ 3.16 |
| C++ 编译器 | 支持 C++17 (GCC ≥ 8 / Clang ≥ 7) |
| Node.js | ≥ 18 LTS |
| npm | 随 Node.js 安装 |

## C++ 代理（pi-guard-agent）

### 3.1 安装系统依赖
```bash
# 构建工具链
sudo apt install -y build-essential cmake pkg-config

# FFmpeg 库（编码器模块依赖）
sudo apt install -y libavcodec-dev libavutil-dev libswscale-dev libswresample-dev libavformat-dev

# ALSA 音频库（音频采集模块依赖）
sudo apt install -y libasound2-dev

# OpenCV（视频预览 CLI 工具依赖）
sudo apt install -y libopencv-dev

# spdlog 日志库
sudo apt install -y libspdlog-dev
```

### 3.2 构建与验证
项目采用 out-of-source 构建方式，构建目录为 `build/agent`：
```bash
# 在项目根目录执行
cmake -B build/agent -S project/agent
cmake --build build/agent -j$(nproc)
```

验证构建结果：
```bash
# 检查主程序
./build/agent/pi-guard-agent

# 运行测试（如已启用）
cd build/agent && ctest --output-on-failure
```

### 3.3 构建选项
```bash
# Debug 构建（保留调试符号）
cmake -B build/agent -S project/agent -DCMAKE_BUILD_TYPE=Debug

# Release 构建（性能优化）
cmake -B build/agent -S project/agent -DCMAKE_BUILD_TYPE=Release

# 启用测试
cmake -B build/agent -S project/agent -DBUILD_TESTING=ON
```

### 3.4 CLI 工具
构建完成后，`build/agent/` 下还会生成以下命令行工具：

| 工具 | 用途 |
|------|------|
| `preview-video` | 视频预览（依赖 OpenCV） |
| `record-audio` | 音频录制（依赖 ALSA） |
| `mp4-writer` | MP4 文件写入 |
| `srs-pusher` | SRS RTMP 推流 |

## Node.js 服务器（pi-guard-server）

### 4.1 安装 Node.js
推荐使用 Node.js 18+ LTS：
```bash
# 方法一：通过 NodeSource 安装（推荐）
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs

# 方法二：通过 nvm 安装
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.0/install.sh | bash
nvm install 20
```

验证：
```bash
node --version   # v20.x.x
npm --version    # 10.x.x
```

### 4.2 安装依赖与运行


其他命令：
```bash
npm run build      # TypeScript 编译
npm run start      # 运行编译产物
npm run typecheck  # 类型检查
```

## SRS 流媒体服务

### 6.1 安装 SRS
```bash
# Ubuntu/Debian
sudo apt install -y srs

# 或从源码构建
git clone https://github.com/ossrs/srs.git
cd srs/trunk
./configure && make
```

### 6.2 启动 SRS
使用项目提供的启动脚本：
```bash
bash project/srs/scripts/run-srs.sh
```

或手动指定配置文件启动：
```bash
srs -c project/srs/conf/srs.conf
```

### 6.3 验证 SRS
| 服务 | 地址 |
|------|------|
| RTMP 推流 | `rtmp://localhost:1935/live/stream` |
| HTTP-FLV 播放 | `http://localhost:8080/live/stream.flv` |
| HLS 播放 | `http://localhost:8080/live/stream.m3u8` |
| HTTP API | `http://localhost:1985/api/v1/versions` |

### 6.4 SRS 与服务器联调
SRS 配置了 HTTP Hooks，会回调 Node.js 服务器：
- `on_publish`: `http://127.0.0.1:3000/api/srs/on_publish`
- `on_unpublish`: `http://127.0.0.1:3000/api/srs/on_unpublish`
- `on_hls`: `http://127.0.0.1:3000/api/srs/on_hls`

联调时需确保 Node.js 服务器（端口 3000）先于 SRS 启动。

## IDE 配置（VS Code）

### 7.1 安装 VS Code 扩展
**C++ 开发**（二选一，不可同时启用）：

| 扩展 | 用途 |
|------|------|
| **clangd**（LLVM Extensions） | 推荐。自动读取 compile_commands.json，无需手动配置 include 路径 |
| C/C++（Microsoft） | 微软官方扩展。需手动维护 c_cpp_properties.json |

> 安装 clangd 扩展后，VS Code 会提示禁用微软 C/C++ 扩展，请确认禁用以避免冲突。

**其他推荐扩展**：
- CMake Tools — CMake 项目支持
- ESLint — JavaScript/TypeScript 代码检查
- Prettier — 代码格式化

### 7.2 clangd 配置
项目根目录已有 `.clangd` 配置文件，内容如下：
```yaml
CompileFlags:
  CompilationDatabase: build/agent
```

该配置告诉 clangd 到 `build/agent/` 目录下查找 `compile_commands.json`。

**首次使用需确保**：
1. 已完成 C++ 代理的 CMake 配置（生成 `compile_commands.json`）：
   ```bash
   cmake -B build/agent -S project/agent
   ```

2. 已安装 clangd 命令行工具：
   ```bash
   sudo apt install -y clangd
   ```

3. 重启 clangd 语言服务器：`Ctrl+Shift+P` → `clangd: Restart language server`

### 7.3 验证 IDE 配置
打开任意 `.cpp` 文件，检查：
- `#include` 无红色波浪线
- 代码补全正常工作
- `Ctrl+Click` 可跳转到定义

## 常见问题

### C++ 代理构建失败
| 问题 | 解决方案 |
|------|----------|
| `Could not find ALSA` | `sudo apt install libasound2-dev` |
| `Could not find spdlog` | `sudo apt install libspdlog-dev` |
| `Could not find OpenCV` | `sudo apt install libopencv-dev` |
| `Could not find libavcodec` | `sudo apt install libavcodec-dev libavutil-dev libswscale-dev libswresample-dev` |
| `Could not find libavformat` | `sudo apt install libavformat-dev` |
| CMake 版本过低 | 升级 CMake：`sudo pip3 install cmake --upgrade` 或从 [cmake.org](https://cmake.org/download/) 下载 |
| C++17 不支持 | 升级编译器：`sudo apt install g++-9` |

### clangd 报错 `Unknown Config key`
clangd 18+ 的 `.clangd` 配置使用 YAML 嵌套格式：
```yaml
# 正确 ✓
CompileFlags:
  CompilationDatabase: build/agent

# 错误 ✗（旧版格式）
CompileCommands: build/agent/compile_commands.json

# 错误 ✗（顶层级键名）
CompilationDatabase: build/agent
```

### clangd 报错 `Failed to find compilation database`
1. 确认已执行 `cmake -B build/agent -S project/agent` 生成 `compile_commands.json`
2. 确认 `.clangd` 文件在项目根目录
3. 重启 clangd：`Ctrl+Shift+P` → `clangd: Restart language server`

### Node.js / npm 问题
| 问题 | 解决方案 |
|------|----------|
| `npm install` 失败 | 删除 `node_modules` 和 `package-lock.json` 后重试 |
| 端口被占用 | `lsof -i :3000` 查找占用进程并终止 |
| TypeScript 编译错误 | 执行 `npm run typecheck` 查看详细错误 |

### SRS 问题
| 问题 | 解决方案 |
|------|----------|
| RTMP 推流失败 | 检查 SRS 是否运行：`curl http://localhost:1985/api/v1/versions` |
| HTTP Hooks 不触发 | 确认 Node.js 服务器已启动且端口 3000 可达 |
| HLS 延迟过高 | 调整 `srs.conf` 中的 `hls_fragment` 和 `hls_window` |

## 故障排查指南

### C++ 代理（Linux/Ubuntu/树莓派）
- **缺少 ALSA 开发库**：安装 libasound2-dev；运行时通常 libasound2 已存在。
- **缺少 OpenCV**：安装 libopencv-dev（用于 preview-video 工具）。
- **缺少 spdlog**：安装 libspdlog-dev（若启用 spdlog 日志后端）。
- **缺少 FFmpeg 库**：安装 libavcodec-dev、libavutil-dev、libswscale-dev、libswresample-dev、libavformat-dev。
- **构建失败（CMake 版本过低）**：升级 CMake 至 ≥ 3.16。
- **构建失败（C++17 不支持）**：更换支持 C++17 的 g++/clang++。
- **视频采集无画面**：检查 /dev/videoX 是否存在、权限与格式（YUYV）。
- **音频采集无声**：检查 ALSA 设备名称、采样率与声道数配置。

### Node.js 服务器（Koa + TypeScript）
- **依赖缺失**：执行 npm ci 或 npm install 安装依赖。
- **端口冲突**：修改 package.json 中的端口或停止占用进程。
- **类型检查失败**：修复 TypeScript 错误后再进行构建。

### React 前端（Vite + React）
- **依赖缺失**：执行 npm ci 或 npm install 安装依赖。
- **ESLint 报错**：根据提示修复代码风格或忽略规则。
- **构建失败**：检查 vite.config.ts 与 tsconfig 配置。

### SRS 推流服务
- **RTMP/HLS 不可用**：检查 srs.conf 中端口与路径配置。
- **HTTP API 无法访问**：确认 HTTP API 端口与防火墙设置。
- **与服务器钩子通信失败**：检查钩子回调地址与服务器可达性。
